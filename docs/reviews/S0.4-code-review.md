## 2. Conformité à la spec Cooklang & au format projet (§8.4)

| Marqueur | Smoke-test | Réf. architecture §8.4 | Verdict |
|---|---|---|---|
| Frontmatter `servings` | `servings: 4` | requis | ✓ |
| `@nom{qty%unit}` | 8 occurrences, multi-mots OK | `@ingrédient{quantité%unité}` | ✓ |
| `#ustensile{}` | 3, accolades sur noms multi-mots | `#ustensile` / `#cookware` (FR4) | ✓ |
| `~{durée%unité}` | 2 | `~{durée}` | ✓ |
| Verrou `=` | `@four{=180%°C}` | `=` posé par le moteur pour `fixed` | ✓ |
| Notes `--` | 5, dont `[SÉCURITÉ]`/`[TECHNIQUE]` | `--` portées moteur + LLM | ✓ |

**Usage du `=` (point adversarial demandé).** Le `=` n'existe pas comme « verrou » dans la spec
Cooklang **canonique** (où il sert plutôt à fixer un nom d'affichage). Ici il est employé comme
**convention interne du moteur de scaling** pour marquer une valeur `fixed` (température jamais
multipliée). C'est **explicitement documenté** :
- dans l'architecture §8.4 elle-même (`@sel{=1%c.à.c}`, « `=` posé par le moteur pour `fixed` ») —
  donc c'est un marqueur **projet** assumé, pas une erreur ;
- dans le rapport §(a) et §Conclusion réserve (3) : « le verrou `=` est une convention interne de
  notre moteur de scaling — le plugin l'affiche comme une quantité, ce qui est acceptable » ;
- cohérent avec C1 (AC5, `fixed=True`) et la table de scaling (`categories.temperature.type=fixed`).

→ **Correctement explicité.** Le reviewer juge cet usage non litigieux : il est tracé, justifié et
cohérent inter-documents. Le rapport ne prétend pas que c'est du Cooklang canonique.

**Réserve unités FR** (`c.à.s`, `gousse`, `tranches`, `feuilles`) : la spec canonique attend une
quantité numérique/fractionnaire après `%` ; le projet met du texte d'unité FR. C'est **honnêtement
signalé** comme réserve §(a) et §Conclusion(1), justifié (scaling fait en amont par le moteur, pas
par Cooklang), et non bloquant. Conforme à la décision #3 (templating maison).

- Le rapport §(e) est titré « Capture (**à réaliser manuellement**) » et énonce : « C'est le seul AC
  de S0.4 qui reste **non vérifié programmatiquement** ». La Conclusion distingue explicitement
  « Vérifié programmatiquement » vs « Reste manuel ».
- Le statut est laissé à `review` (et non `done`), avec la phrase « Tant que la capture n'est pas
  fournie, la compatibilité reste attestée structurellement mais pas visuellement ».

→ **Honnêteté irréprochable.** Aucun mensonge de complétion. La distinction vérifié/manuel est
répétée à chaque niveau (story + rapport).

**Placeholder `.png`** : le rapport présente l'emplacement `docs/cooklang/obsidian-render.png` comme
*réservé* et fournit le snippet Markdown commenté à dé-commenter après dépôt. C'est honnête. **Mais**
le fichier placeholder n'existe pas physiquement (cf. finding M-1) — ce qui est cohérent avec « à
produire », sans tromperie, mais mérite une note de complétude.

### Mineurs / observations

- **M-1 [Mineur — capture manuelle en réserve].** Le placeholder `obsidian-render.png` n'existe pas

  texte. **Dismiss** : aucun impact sur le parsing, vérifié.

- **M-3 [Observation — dismiss] Double rôle du `@four{=180%°C}`.** Il apparaît à la fois dans la
  liste « ingrédients » et « verrou = » du contrôle. C'est attendu (un ingrédient à quantité figée)
  et le rapport §(b) l'explicite. **Dismiss.**

## Verdict

**APPROUVÉE — 0 bloquant / 0 majeur.**

Contrôle structurel re-exécuté **indépendamment** : 9/9 conforme, reproductible à l'identique, pas de
gonflage. Marqueurs conformes au format projet §8.4 (y compris l'usage `=` correctement explicité
comme convention interne). UTF-8 sans BOM confirmé. Périmètre propre (rien dans `recipes/`,
`sprint-status.yaml` intact). Complétion **honnête** : la capture manuelle est partout marquée comme
non réalisée, sans mensonge.

**Transition d'état recommandée.** La seule réserve (M-1, capture absente) est l'étape **manuelle
intrinsèque** d'une validation visuelle, déjà honnêtement documentée. Deux lectures possibles :

1. **`done` avec capture en réserve** : justifiable, car tout ce qui était automatisable est livré et
   prouvé, et la story isole proprement l'action humaine résiduelle.
2. **Rester `review` jusqu'à la capture** : c'est ce que la story prescrit elle-même
   (« tant que la capture n'est pas fournie… »).

→ **Recommandation du reviewer : laisser S0.4 en `review` jusqu'au dépôt de
`docs/cooklang/obsidian-render.png` + cochage de la checklist §(d), puis basculer en `done`.** Motif :
la DoD backlog porte explicitement sur « ouvrable dans Obsidian » avec `_AC : capture` ; passer
`done` sans la preuve visuelle viderait l'AC de sa substance. La part automatisable est néanmoins
**approuvée sans réserve** — aucun retour dev nécessaire, seule l'action utilisateur reste à exécuter.
