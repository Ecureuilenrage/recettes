## Story

En tant que **développeur de la couche web (orchestrateur, `app/main.py`)**,
je veux **réécrire `app/main.py` en ASSEMBLEUR du pipeline : une fonction pure d'orchestration `run_pipeline(request, *, complete=None, index=None) -> GenerationResponse` qui câble les 4 couches dans l'ordre du flux bout-en-bout (archi §7 : `translate → neighbors → filter_neighbors → techniques_for/forbidden_cookware/safety → build_prompt → generate_recipe(+validate) → scale/scale_eggs → to_cooklang/to_markdown`), les schémas Pydantic d'API (archi §9.1 : `GenerationRequest`/`GenerationResponse`/`DebugInfo`/`Constraints`), une petite hiérarchie d'exceptions d'orchestration (`PipelineInputError` → 422, `PipelineGenerationError` → 502) et une enveloppe FastAPI MINCE (`POST /generate` + `GET /health` conservé) qui traduit ces exceptions en `HTTPException`**,
afin de **réaliser l'assemblage du système (archi §3.1 : `main → {1, 2, 3, 4}` — E1 est le SEUL module autorisé à importer les 4 couches ; aucune couche métier ne s'importe entre elles) en ne contenant AUCUNE logique métier (E1 ORCHESTRE, il n'invente rien : il appelle les fonctions des couches et traduit les erreurs en codes HTTP), tout en gardant le cœur `run_pipeline` TESTABLE SANS HTTP, SANS appel LLM réel et SANS clé/fichier de données grâce aux coutures injectables `complete` (couche 4) et `index` (couche 1) — R7**.

## Acceptance Criteria

1. **AC1 — `run_pipeline` câble le pipeline bout-en-bout (archi §7), TESTABLE OFFLINE** : `run_pipeline(request, *, complete=None, index=None) -> GenerationResponse` enchaîne, DANS L'ORDRE archi §7 : (a) `translate(request.hero)` → clé Epicure ; (b) vérifie `request.cuisine ∈ load_cuisines()` ; (c) `index.neighbors(clé, k)` (index paresseux `EpicureIndex(model)` si non injecté) ; (d) `filter_neighbors(...)` → `FilteredNeighbors` ; (e) couche 2 `techniques_for` / `forbidden_cookware` / `load_safety` ; (f) `build_prompt(...)` ; (g) `generate_recipe(prompt, complete=complete, validate=lambda r: validate_recipe(r, techniques, safety, frozenset(forbidden)), max_retries=1)` ; (h) scaling APRÈS rédaction (`k = servings / recipe.servings`) ; (i) `to_cooklang` + `to_markdown` ; (j) `DebugInfo`. Le cœur est appelable avec un FAUX `complete` (renvoie une `StructuredRecipe`/dict) et un FAUX `index` (`.neighbors(name, k)`) → AUCUN appel réseau, AUCUNE clé, AUCUN fichier de données requis (R7).
2. **AC2 — Schémas Pydantic (archi §9.1) sous import gardé + fallback** : `Constraints{diet:list[str]=[], no_cookware:list[str]=[], highlight:str|None=None}`, `GenerationRequest{hero:str, cuisine:str="italian_savory_v1", constraints:Constraints=…, servings:int, model:str="cooc"}`, `DebugInfo{epicure:dict, scaling:list[dict], techniques:list[dict]|dict, validation:dict}`, `GenerationResponse{cooklang:str, markdown:str, debug:DebugInfo}` sont définis sous un import GARDÉ de pydantic (patron `try: import … except ImportError`). Si pydantic est ABSENT, une dégradation propre (fallback dataclasses stdlib, mêmes champs/défauts) maintient `run_pipeline` testable sans fastapi/pydantic.
3. **AC3 — Erreurs → HTTP via exceptions d'orchestration (archi §9.1/§6.2)** : `main.py` définit `PipelineInputError` (→ 422) et `PipelineGenerationError` (→ 502). `run_pipeline` LÈVE ces exceptions (pas de dépendance fastapi) : `translate`/`neighbors` `KeyError` → `PipelineInputError` (422) ; cuisine inconnue → `PipelineInputError` (422) ; `RecipeValidationError`/`RecipeGenerationError` (couche 4) → `PipelineGenerationError` (502). L'enveloppe `POST /generate` les mappe en `HTTPException` (422 / 502 ; 500 inattendu ; 200 succès).
4. **AC4 — Endpoint FastAPI = enveloppe MINCE, `/health` conservé, coutures d'injection** : sous `if FastAPI is not None`, `POST /generate` appelle `run_pipeline` et traduit ses exceptions en `HTTPException` (AUCUNE logique métier dans l'enveloppe). `GET /health` est CONSERVÉ (`{status, stage}`). Une couture d'injection (`Depends(get_index)` / `Depends(get_complete)`, surchargeables via `app.dependency_overrides`) permet à un test TestClient de tourner SANS clé ni données réelles.
5. **AC5 — Scaling APRÈS rédaction, debug complet (FR7, archi §7/§9.1)** : le scaling (couche 3) s'applique APRÈS la rédaction LLM, sur les quantités de BASE (`recipe.servings`), avec `k = request.servings / recipe.servings` : `scale_eggs` pour les œufs (nom contenant « oeuf »/« œuf »), `scale(name, amount, unit, k)` sinon. `DebugInfo` porte les 4 sections : `epicure=filtered.to_debug()` ; `scaling=[{name,type,coeff,formula,reasoning,value}…]` (depuis `ScaledQuantity.debug`) ; `techniques={kept:[t.id…], excluded:[{technique_id,forbidden_tool,via_constraint}…]}` (via `excluded_techniques`) ; `validation=` re-appel déterministe `validate_recipe(...)` sérialisé `{ok, violations, feedback}`.
6. **AC6 — Règle archi §3.1 (E1 = SEUL assembleur) + suite verte 0 régression** : (a) `app/main.py` importe les 4 couches (`app.epicure`/`app.knowledge`/`app.scaling`/`app.generator`) — c'est le SEUL module autorisé à le faire (archi §3.1) ; il ne contient AUCUNE logique métier (uniquement orchestration + glu de conversion entre les 2 dataclasses `Constraints` des couches 1 et 2). (b) `tests/test_main.py` **vert** (ciblé) ; suite : **baseline 160 passed / 1 skipped** → 160 + nouveaux tests offline, **0 régression** (le 1 skipped = intégration Claude, reste skippé).

## Dev Notes

### E1 EST L'ASSEMBLEUR (archi §3.1)

- E1 (`app/main.py`) est le **SEUL** module autorisé à importer les 4 couches (`main → {1, 2, 3, 4}`). Les couches ne s'importent JAMAIS entre elles. E1 ne contient **AUCUNE logique métier** : il ORCHESTRE (assemble le pipeline + traduit les erreurs en codes HTTP) en appelant les fonctions publiques des couches. La SEULE « glu » admise est la conversion entre les deux dataclasses `Constraints` (couche 1 `app.epicure.Constraints` ET couche 2 `app.knowledge.Constraints` ont chacune LEUR type ; E1 construit le bon pour chaque appel) et l'adaptation de la requête (duck-typing).
  [Source : docs/architecture.md#3.1 (règle de dépendances, E1 = orchestrateur sans logique métier), #7 (flux), #9.1 (API)]

### API publique des couches câblées (vérifiée en lecture)

- **Couche 1** (`from app.epicure import …`) : `translate(fr_term) -> str` (lève `KeyError` si terme FR absent) ; `EpicureIndex(model).neighbors(name, k) -> list[tuple[str, float]]` (lève `KeyError` si clé absente du vocab) ; `filter_neighbors(candidates, cuisine, Constraints) -> FilteredNeighbors` (`.kept`, `.rejected`, `.to_debug()`) ; `Constraints{diet, no_cookware, highlight}`.
- **Couche 2** (`from app.knowledge import …`) : `techniques_for(cuisine, ingredient, Constraints) -> list[Technique]` ; `forbidden_cookware(cuisine, Constraints) -> set[str]` ; `safety_for(food_type)` ; `load_safety() -> SafetyTable` ; `load_cuisines() -> dict[str, Cuisine]` ; `excluded_techniques(cuisine, ingredient, Constraints) -> list[Exclusion{technique_id, forbidden_tool, via_constraint}]` ; `Constraints{diet, no_cookware, highlight}`.
- **Couche 3** (`from app.scaling import …`) : `scale(name, qty, unit, k) -> ScaledQuantity{name, value, unit, type, fixed, notes, reserve, debug}` ; `scale_eggs(count, k) -> ScaledEggs{whole_eggs, remainder, note, type, debug}` ; `scale_time(minutes, k) -> ScaledTime`.
- **Couche 4** (`from app.generator import …`) : `build_prompt(req, neighbors, techniques, safety, forbidden) -> ConstrainedPrompt` (req duck-typé : `hero`/`cuisine`/`servings`) ; `generate_recipe(prompt, complete=None, validate=None, max_retries=1) -> StructuredRecipe` (lève `RecipeGenerationError`/`RecipeValidationError`) ; `validate_recipe(recipe, techniques, safety, forbidden=frozenset()) -> ValidationResult{ok, violations, feedback}` ; `to_cooklang(recipe, scaling_notes=None) -> str` ; `to_markdown(recipe) -> str` ; `StructuredRecipe`/`Quantity`/… ; `RecipeGenerationError`/`RecipeValidationError`.
  [Source : app/epicure/__init__.py, app/knowledge/__init__.py, app/scaling/__init__.py, app/generator/__init__.py — TOUS les exports nécessaires sont déjà disponibles (aucun export manquant à fusionner par l'orchestrateur).]

### Ordre du flux (archi §7) — décisions de câblage

- `translate(hero)` AVANT `neighbors` (la clé Epicure est en anglais snake_case ; le héros saisi en FR doit être traduit). `KeyError` de `translate` OU de `neighbors` → 422 (héros hors vocab).
- `safety` passé à `build_prompt`/`validate_recipe` = `load_safety()` (table complète) : décision documentée — le générateur cite la (les) ligne(s) pertinente(s), et le validateur s'appuie sur la table pour autoriser les minima de sécurité. (Le helper `safety_for(hero)` reste disponible pour un futur filtrage ciblé ; non requis ici.)
- **Scaling APRÈS rédaction** (archi §7, isole le non-déterminisme LLM du calcul de quantités) : `k = request.servings / recipe.servings` (recipe.servings = portions de BASE). `scale_eggs` si l'ingrédient est un œuf (nom contenant « oeuf »/« œuf », « œ » replié sur « oe »), sinon `scale`. Les `ScaledQuantity` non-œufs alimentent `to_cooklang(scaling_notes=…)` ; une `StructuredRecipe` scalée (via `dataclasses.replace` des ingrédients) alimente `to_markdown`. `k == 1` → scaling neutre.
- **Œufs** : `scale_eggs(count, k)` rend `whole_eggs` (entier) ; E1 remplace l'ingrédient par sa quantité entière scalée pour le markdown et journalise `type="discrete"` + la note RZ1 dans `debug.scaling`. Le reliquat volumique (`remainder`) reste documenté dans la note ; décision par défaut (mode non-interactif) : E1 n'ajoute pas d'ingrédient « reste battu » distinct (simplicité v1).
  [Source : docs/architecture.md#7 (étapes 4→7, scaling après rédaction), #5.4/§5.5 (scaling œufs/temps) ; app/scaling/engine.py (`scale`/`scale_eggs`)]

### Erreurs → HTTP (archi §9.1/§6.2)

- Hiérarchie d'orchestration définie DANS `main.py` (aucune dépendance fastapi dans `run_pipeline`) : `PipelineError` (base) → `PipelineInputError` (422) / `PipelineGenerationError` (502). `run_pipeline` lève ces exceptions ; l'enveloppe `POST /generate` les TRADUIT en `HTTPException` (422 entrée invalide ; 502 échec LLM / violation persistante ; 500 inattendu ; 200 succès).
- `generate_recipe` applique déjà la politique « rejet + 1 retry, sinon échec propre » (archi §6.2, D9) : E1 passe `validate=lambda r: validate_recipe(r, techniques, safety, frozenset(forbidden))` et `max_retries=1`, et mappe `RecipeValidationError`/`RecipeGenerationError` → 502.
  [Source : docs/architecture.md#9.1 (codes 200/422/502/500), #6.2 (retry/échec) ; app/generator/client.py (`generate_recipe`, exceptions)]
