## Story

En tant que **mainteneur du dépôt (vitrine portfolio)**,
je veux **un `README.md` racine clair et à jour maintenant que la v1 est livrable en local (pitch,
architecture 4 couches, comment lancer, exemple de recette générée + panneau debug, périmètre,
documentation, crédits) ET un fichier `NOTICE` à la racine attribuant les embeddings Epicure
(© 2026 Jakub Radzikowski & Josef Chen, KAIKAKU.AI) sous licence CC BY 4.0**,
afin de **présenter le projet comme un portfolio cohérent (le panneau debug comme vitrine
d'explicabilité), de permettre à un lecteur de lancer l'app en local, et de satisfaire l'exigence
d'attribution Epicure CC BY 4.0 (R10 / archi §13) et le critère PRD §5 « Licence » (fichier
`LICENSE`/`NOTICE` mentionnant « Epicure — CC BY 4.0 » présent à la racine)**.

## Acceptance Criteria

1. **AC1 — README portfolio clair et à jour** : `README.md` (racine) présente, dans cet ordre
   lisible : (a) un **pitch** concis du scaler honnête (scaling déterministe non-linéaire par
   ingrédient + grounding sécurité ; LLM = rédacteur sous contraintes) ; (b) l'**architecture
   4 couches** (Associations Epicure / Base technique grounded / Moteur de scaling = pièce
   maîtresse / Générateur LLM) avec la **règle de dépendances** « `main → {1,2,3,4}`, les couches ne
   s'importent pas entre elles » (testabilité) ; (c) un **périmètre v1** (in/out) ; (d) une **table
   de documentation** (liens vers `docs/`, `pitch.md`, `NOTICE`). Le statut d'en-tête reflète que la
   **v1 est livrable en local** (et non « à venir »).
2. **AC2 — Comment lancer en local** : le README contient une section **« Comment lancer en
   local »** opérationnelle : `pip install -r requirements.txt` ; téléchargement des embeddings
   Epicure dans `data/epicure/` (gitignoré) via `huggingface_hub` (modèle `Kaikaku/epicure-cooc`) ;
   `export ANTHROPIC_API_KEY=...` ; `uvicorn app.main:app --reload` ; **exemple de corps JSON**
   `POST /generate` `{hero, cuisine, constraints, servings, model}` + mention de `GET /health` et des
   codes `200/422/502`. Mention explicite que les **tests tournent sans clé ni réseau**
   (`python -m pytest -q`) grâce à la couture `complete` injectable (faux LLM) de `run_pipeline`, et
   **note honnête** : `fastapi` requis (déjà dans `requirements.txt`) ; sans données Epicure locales
   l'app web réelle ne génère pas, mais la logique est testée offline.
3. **AC3 — Exemple de recette générée + panneau debug (vitrine d'explicabilité, archi §9.2)** : le
   README montre un **extrait `.cook` réaliste** (frontmatter `servings`, marqueurs `@`/`#`/`~`,
   verrou `=`, notes `--`) ET un **extrait du panneau debug** restituant les 4 sections de
   `DebugInfo` (archi §9.1) : `epicure` (voisins retenus/rejetés), `scaling` (par ingrédient :
   type/coeff/formule/raisonnement), `techniques` (retenues/exclues + cookware interdit),
   `validation` (garde-fou). L'exemple est **illustratif** et marqué comme tel, cohérent avec la base
   italienne `italian_savory_v1`.
4. **AC4 — Attribution Epicure CC BY 4.0 dans le README** : le README contient une section
   **« Crédits & licence »** qui attribue **Epicure © 2026 Jakub Radzikowski & Josef Chen
   (KAIKAKU.AI)** sous **CC BY 4.0** avec le lien licence et [arXiv 2605.22391], précise que
   l'attribution est **requise**, que le projet **ne redistribue pas le corpus** (non publié) mais
   seulement les **vecteurs publics** (`Kaikaku/epicure-cooc`), crédite le format **Cooklang**
   (cooklang.org), et **renvoie vers le fichier `NOTICE`**.
5. **AC5 — Fichier `NOTICE` à la racine (critère PRD §5)** : un fichier **`NOTICE`** existe à la
   **racine** et mentionne explicitement « **Epicure — CC BY 4.0** » : © 2026 Jakub Radzikowski &

### Cohérence avec l'API et le pipeline réels (lecture seule de `app/main.py`)

- `run_pipeline(request, *, complete=None, index=None)` est le **cœur testable** : injectables
  `complete` (faux rédacteur LLM déterministe) et `index` (faux index Epicure) → testable **sans
  HTTP, sans LLM réel, sans clé/fichier de données** (R7). L'endpoint `POST /generate` est une
  enveloppe MINCE qui mappe les exceptions en `HTTPException` (`PipelineInputError`→422,
  `PipelineGenerationError`→502, autre→500). `GET /health` conservé. `fastapi`/`pydantic` importés de
  façon tolérante (absence → dégradation propre). L'exemple de corps JSON `POST /generate` du README
  reflète `GenerationRequest{hero, cuisine, constraints{diet, no_cookware, highlight}, servings,
  model}` ; la réponse `GenerationResponse{cooklang, markdown, debug:DebugInfo{epicure, scaling,
  techniques, validation}}`.
  [Source : app/main.py (run_pipeline, get_index/get_complete, /generate, /health, schémas §9.1) —
  LECTURE SEULE ; docs/architecture.md#9.1, #7]
