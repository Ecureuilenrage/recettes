## Story

En tant que **développeur du moteur de scaling (couche 3)**,
je veux **une fonction `scale_time(minutes, k)` qui applique la loi géométrique `t × k^(2/3)` (exposant lu dans la table) et émet une note de changement de contenant au-delà d'un seuil de `k`**,
afin de **rendre le temps de cuisson crédible à l'échelle (un plat doublé ne demande pas le double de temps) et de poser la constante de seuil de non-linéarité que C4 réutilisera**.

## Acceptance Criteria

1. **AC1 — Loi géométrique** : `scale_time(20, 2.0)` retourne `~32 min` (`20 × 2^0.6667 ≈ 31.75`, cible backlog « ~32, pas 40 »). L'**exposant est lu dans la table** (`categories[]` temps, `exponent: 0.6667`) — **jamais codé en dur** dans `engine.py`.
2. **AC2 — Constante de seuil (RZ2)** : une constante `K_NONLINEAR_THRESHOLD = 1.5` est définie **une seule fois** dans `app/scaling/engine.py`, commentée `# à calibrer F2` et `# RZ2`. Elle est **partagée avec C4** (ne pas la redéfinir ailleurs) ; C4 l'importera depuis `engine.py`.
3. **AC3 — Note de changement de contenant** : une note `--` (changement/adaptation de contenant, ex. « -- à fort facteur, privilégier une cocotte large, réduction plus longue ») est émise **quand `k ≥ K_NONLINEAR_THRESHOLD`**. En deçà du seuil, aucune note de contenant n'est émise.
4. **AC4 — Sortie structurée** : `scale_time(...)` retourne un `ScaledTime` exposant **au minimum** : `minutes: float` (temps scalé), `nonlinear: bool` (toujours `True` pour le temps — type `geometric`/`nonlinearFlag`), `note` (note `--` ou liste de notes ; vide/`None` quand `k < seuil`).

## Dev Notes

### Contexte architectural (à respecter impérativement)

- **Contrat de pureté (OA1, archi §5.1)** : `app/scaling/` est **pur et déterministe** — aucun I/O réseau, aucun LLM, aucun état mutable global. `scale_time` ne lit que la table (via `classify`, cache C1) ; même `(minutes, k)` → **exactement** le même `ScaledTime`. C'est ce contrat qui rend C5 testable.
  [Source : docs/architecture.md#5.1-Contrat-de-pureté]
- **Aucun coefficient/exposant codé en dur (D7, DoD C3)** : l'exposant `0.6667` provient de `table-scaling-sale.json` (`categories[]` temps, `exponent`). Le module la **lit**, ne la **fige** pas ; la calibration (F2) modifiera la table, jamais le code. Un `0.6667` littéral dans `engine.py` est une violation directe de la DoD et du contrat « coeffs en table ».
  [Source : docs/architecture.md#12 (D7) ; docs/scaling/table-scaling-sale.json#meta.disclaimer]
- **Type `geometric` (archi §5.2, §5.5)** : `t_scaled = t × k^(2/3)`. La table fournit `geometricTimeExamples` (×1.5→1.31, ×2→1.59, ×3→2.08, ×4→2.52) pour vérification : `20 × 1.59 = 31.8 ≈ 32`. Le temps porte `nonlinearFlag: true`.
  [Source : docs/architecture.md#5.2, #5.5 « Temps (scale_time, C3) » ; docs/scaling/table-scaling-sale.json#geometricTimeExamples]

### Réserve RZ2 — seuil de non-linéarité (point central de C3)

- **Problème (readiness-check)** : le seuil de `k` déclenchant la note de changement de contenant / le flag de non-linéarité n'est **pas chiffré** dans la table. L'architecture pose l'**[HYPOTHÈSE]** d'un alignement sur le flag de non-linéarité (~1.5–2×), **à confirmer en calibration**.
- **Décision figée pour C3** : `K_NONLINEAR_THRESHOLD = 1.5`, définie **une fois** dans `engine.py`, commentée `# RZ2— à calibrer F2`. Cette constante est **partagée avec C4** (`reserves.RZ2.story: [C3, C4]`) : C4 l'**importe**, ne la redéfinit pas. C'est l'unique source de vérité du seuil.
- **Note de contenant** : règle `rules[0]`/`rules[2]` de la table — « raisonner profondeur/surface » et « ne se double pas proprement au-delà de ~1.5–2× ». Émettre une note `--` (style Cooklang) lorsque `k ≥ seuil`.
  [Source : docs/architecture.md#5.5 « Géométrie / contenant », « Flag de non-linéarité » + [À TRANCHER]/[HYPOTHÈSE] ; docs/scaling/table-scaling-sale.json#rules ; docs/stories/sprint-status.yaml#reserves.RZ2]
